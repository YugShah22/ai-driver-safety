# Database Documentation

## AI Driver Safety & Intelligence Platform

---

## Overview

The database is hosted on **Supabase PostgreSQL**. All tables are in the `public` schema.
Row Level Security (RLS) is enabled on every user-owned table — users can only access their own data.

---

## Running the Migration

Copy the SQL from `supabase/migrations/001_initial_schema.sql` and paste it into the
**Supabase SQL Editor** for your project.

```
Supabase Dashboard → SQL Editor → New query → Paste → Run
```

## Tables

### `profiles`

Auto-created from `auth.users` via the `on_auth_user_created` trigger.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key — references `auth.users(id)` |
| `email` | `TEXT` | User email |
| `full_name` | `TEXT` | Optional display name |
| `created_at` | `TIMESTAMPTZ` | Auto-set |

---

### `trips`

One trip = one dashcam video + its analysis results.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key |
| `user_id` | `UUID` | FK → `profiles(id)` |
| `title` | `TEXT` | Human-readable trip name |
| `video_path` | `TEXT` | Supabase Storage path (e.g. `{user_id}/{timestamp}.mp4`) |
| `duration` | `FLOAT8` | Video duration in seconds (set after processing) |
| `status` | `TEXT` | `UPLOADED \| PROCESSING \| ANALYZING \| COMPLETED \| FAILED` |
| `created_at` | `TIMESTAMPTZ` | Auto-set |
| `completed_at` | `TIMESTAMPTZ` | Set when analysis completes |

**Indexes:** `user_id`, `status`, `created_at DESC`

---

### `frames`

Individual frames extracted from the video during processing.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key |
| `trip_id` | `UUID` | FK → `trips(id)` |
| `frame_number` | `INTEGER` | Zero-based frame index |
| `timestamp` | `FLOAT8` | Seconds from video start |
| `image_path` | `TEXT` | Supabase Storage path |

**Indexes:** `trip_id`, `(trip_id, frame_number)`

---

### `detections`

YOLO object detection results per frame.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key |
| `trip_id` | `UUID` | FK → `trips(id)` |
| `frame_id` | `UUID` | FK → `frames(id)` (nullable) |
| `object_type` | `TEXT` | e.g. `car`, `pedestrian`, `bus` |
| `confidence` | `FLOAT8` | 0.0–1.0 |
| `x1, y1, x2, y2` | `FLOAT8` | Bounding box in pixel coordinates |
| `created_at` | `TIMESTAMPTZ` | Auto-set |

**Indexes:** `trip_id`, `frame_id`, `object_type`

---

### `driving_metrics`

Per-timestamp driving metrics. Values are **ESTIMATED** or **INFERRED** from monocular video
(see [limitations.md](./limitations.md)).

| Column | Type | Label | Notes |
|---|---|---|---|
| `timestamp` | `FLOAT8` | — | Seconds from video start |
| `speed` | `FLOAT8` | ESTIMATED | km/h via optical flow — not GPS calibrated |
| `acceleration` | `FLOAT8` | ESTIMATED | m/s² derived from speed delta |
| `lane_deviation` | `FLOAT8` | ESTIMATED | px from lane center |
| `vehicle_density` | `INTEGER` | INFERRED | Vehicle count from YOLO |
| `pedestrian_distance` | `FLOAT8` | ESTIMATED | px from nearest pedestrian bounding box |
| `time_to_collision` | `FLOAT8` | ESTIMATED | Heuristic — not a physical measurement |

---

### `driving_events`

Safety-relevant events detected during analysis.

| Column | Type | Notes |
|---|---|---|
| `event_type` | `TEXT` | e.g. `PEDESTRIAN_PROXIMITY`, `LANE_DEPARTURE`, `HIGH_TRAFFIC_DENSITY` |
| `severity` | `TEXT` | `LOW \| MEDIUM \| HIGH \| CRITICAL` |
| `confidence` | `FLOAT8` | 0.0–1.0 — ML prediction confidence or rule certainty |
| `timestamp` | `FLOAT8` | Seconds from video start |
| `description` | `TEXT` | Human-readable explanation |

**Note:** Events generated by deterministic rules have `confidence = 1.0`.
Events generated by ML models have a model-estimated confidence value.

---

### `risk_predictions`

ANN / ML risk scores per timestamp.

| Column | Type | Notes |
|---|---|---|
| `risk_score` | `FLOAT8` | 0.0–1.0 probability |
| `risk_class` | `TEXT` | `SAFE \| MODERATE \| HIGH` |
| `model_name` | `TEXT` | e.g. `ann_v1`, `xgboost_v1` |
| `model_version` | `TEXT` | Semantic version |

---

### `model_versions`

Registry of deployed ML model versions and their evaluation metrics.

| Column | Type | Notes |
|---|---|---|
| `model_name` | `TEXT` | e.g. `cnn_v1`, `ann_v1` |
| `model_type` | `TEXT` | `CNN`, `ANN`, `XGBOOST`, etc. |
| `version` | `TEXT` | Semantic version |
| `metrics` | `JSONB` | `{"accuracy": 0.91, "f1": 0.88, ...}` — only from actual training |

> ⚠️ Metrics are only inserted after real training and evaluation. No placeholder values.

## Row Level Security

Every user-owned table (trips, frames, detections, driving_metrics, driving_events, risk_predictions)
has RLS enabled with policies that scope all operations to the authenticated user's `user_id`.

The `model_versions` table is readable by all authenticated users (model registry is shared).

Backend writes (via FastAPI service-role key) bypass RLS — this is intentional and safe because
the backend enforces its own ownership checks before writing.

## Storage Buckets

| Bucket | Public | Max size | Allowed types |
|---|---|---|---|
| `videos` | ❌ | 500 MB | mp4, mov, avi, webm |
| `frames` | ❌ | 5 MB | jpeg, png, webp |
| `model-artifacts` | ❌ | 2 GB | any |

Storage RLS: users can only read/write their own folder (`{user_id}/...`).
Model artifacts are read-only for users — only the service-role (backend) can write.

## Trigger

```sql
-- Auto-creates a profile row when a new auth user signs up
CREATE TRIGGER on_auth_user_created
    AFTER INSERT ON auth.users
    FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

The `handle_new_user()` function copies `id`, `email`, and `full_name` (from user metadata)
into the `profiles` table. The frontend passes `full_name` in the `options.data` field of
`supabase.auth.signUp()`.
